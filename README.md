# HomeRadar

**HomeRadar** — локальное Android-приложение для построения карты Wi-Fi-сигнала вдоль пройденного маршрута.

Пользователь проходит по помещению со смартфоном, а приложение должно:
- оценивать перемещение телефона по камере и инерциальным датчикам;
- собирать доступные Wi-Fi-наблюдения;
- привязывать измерения к координатам и времени;
- рисовать линию пройденного маршрута;
- показывать уровень сигнала в местах измерений;
- сохранять проходы и сравнивать результаты в разные дни.

> **План здания не нужен.** Основная карта — свободное 2D-поле с траекторией и точками Wi-Fi-измерений. Распознавание комнат, стен и ручное черчение плана не входят в базовый сценарий.

## Текущее состояние

Проект находится на стадии работающего прототипа сбора данных и приблизительной траектории.

**Уже реализовано:**
- переносимый Rust Core: типы времени/позиций/Wi-Fi, сегментация траектории, интерполяция и агрегация RSSI;
- Android-приложение на Kotlin и Jetpack Compose Material 3;
- Wi-Fi scanner с SSID, BSSID, RSSI, частотой и свежестью измерений;
- сбор IMU-событий и rotation vector;
- запись приблизительного маршрута по встроенному датчику шагов и относительному азимуту;
- экран начала/завершения прохода и живая линия маршрута на пустом 2D-поле;
- привязка свежих Wi-Fi-измерений к траектории по timestamp, только когда положение можно интерполировать между сенсорными отсчётами;
- цветные точки Wi-Fi по уровню RSSI без заполнения неизмеренных областей.

**Ограничения текущего прототипа:**
- длина шага пока фиксирована оценкой 0,68 м; ошибка положения накапливается;
- направление берётся из rotation vector/магнитного азимута, поэтому на него влияют калибровка, ориентация телефона и магнитные помехи;
- камерное позиционирование ARCore и полноценное объединение камеры с IMU ещё не подключены;
- сессии пока не сохраняются после закрытия приложения; SQLite и формат проекта homeradar ещё впереди;
- Wi-Fi сканируется по запросу и через доступные системные обновления: Android может отклонять запросы и ограничивает частоту сканирования;
- Rust Core пока не подключён к Kotlin через UniFFI/JNI.

Смотри [план разработки](docs/ROADMAP.md).

## Архитектура

- **Rust Core** — переносимые модели, временная синхронизация, траектория, Wi-Fi-обработка и Heatmap. Ядро не зависит от Android.
- **Kotlin Android** — разрешения, Wi-Fi API, сенсоры, будущая камера, жизненный цикл и интерфейс.
- **Jetpack Compose + Material 3** — Android UI и Material You.
- **PDR fallback** — предварительная оценка маршрута по шагам и направлению; это не замена visual-inertial tracking.
- **ARCore** — планируемый необязательный источник visual-inertial pose на совместимых устройствах.
- **UniFFI** — предпочтительный вариант связи Rust и Kotlin после отдельного прототипа.
- **Локальное хранение** — SQLite и архив проекта на следующих этапах.

## Принципы

1. **Trajectory-first:** карта маршрута важнее модели помещения.
2. **Никаких выдуманных измерений:** время измерения Wi-Fi хранится отдельно от времени получения результата.
3. **Старые результаты остаются старыми:** кэшированные сканы не считаются свежими.
4. **Mesh — гипотеза, пока нет доказательств:** одинаковый SSID не означает один физический AP.
5. **Неопределённость видна:** потеря tracking и временные разрывы не соединяются выдуманной линией.
6. **Локально по умолчанию:** нет обязательного аккаунта, облака, телеметрии или автоматической загрузки.
7. **Повторная обработка:** исходные наблюдения должны храниться отдельно от производных карт.

## Сборка Rust Core

Из корня репозитория:

    cd core
    cargo test --workspace
    cargo run -p homeradar-core --example synthetic_walk

На текущем этапе Rust Core использует только стандартную библиотеку.

## Сборка Android-приложения

Требуются JDK 17, Android SDK Platform 37 и Gradle 9.5.0. Подробности находятся в [android/README.md](android/README.md).

## Разрешения Android

- ACCESS_FINE_LOCATION используется для доступа к Wi-Fi scan results по требованиям Android.
- ACTIVITY_RECOGNITION запрашивается при запуске записи маршрута, потому что встроенный датчик шагов требует это разрешение на Android 10+.
- Приложение не запрашивает GPS-координаты для локальной карты маршрута.
