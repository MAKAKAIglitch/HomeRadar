# Android application

HomeRadar — Android-приложение на Kotlin и Jetpack Compose Material 3.

## Требования

- JDK 17.
- Android SDK Platform 37.
- Gradle 9.5.0 (build scripts скачивают его при отсутствии подходящей локальной версии).
- Android Gradle Plugin 9.3.1.
- Kotlin Gradle Plugin / Compose compiler 2.4.21.

## Сборка на Linux

Из корня репозитория:

    bash ./build.sh

Скрипт:
- проверяет JDK и Android SDK Platform 37;
- использует установленный Gradle 9.5.0 или скачивает binary-only distribution в пользовательский cache;
- сверяет SHA-256 архива Gradle с checksum, опубликованным Gradle;
- запускает только :android:app:assembleDebug, без тестовых/лишних задач;
- ограничивает Gradle двумя worker-потоками и отключает daemon для этой сборки.

Готовый APK:

    android/app/build/outputs/apk/debug/app-debug.apk

## Сборка на Windows

Из корня репозитория:

    build.bat

Или напрямую через PowerShell:

    .\build.ps1

Нужны JDK 17 и Android SDK Platform 37. Gradle 9.5.0 будет загружен и проверен по SHA-256 при первом запуске, затем переиспользуется из %LOCALAPPDATA%\HomeRadar\Gradle.

## GitHub Actions

Workflow .github/workflows/android-build.yml собирает APK только на ubuntu-latest.

- Автоматический запуск — только при push в main, если изменены файлы приложения, Gradle-конфигурация или build scripts.
- Ручной запуск доступен через workflow_dispatch.
- Pull request, расписания, Windows runner и отдельные тестовые matrix jobs не включены.
- Используется JDK 17, Android SDK Platform 37 и Gradle 9.5.0.
- Gradle cache использует базовый open-source provider.
- Загружается один debug APK; срок хранения артефакта — 3 дня.

После успешного workflow APK находится в разделе Actions → соответствующий запуск → Artifacts.

## Реализовано

- Android Activity и Compose Material 3 UI.
- Определение SSID активного Wi-Fi-подключения через ConnectivityManager / NetworkCapabilities / WifiInfo, с legacy fallback.
- Выбор целевой сети перед проходом: подключённая сеть выбрана по умолчанию; можно выбрать другую обнаруженную сеть или «Все сети». Выбор сохраняется локально.
- Запрос ACCESS_FINE_LOCATION перед чтением Wi-Fi scan results.
- Регистрация системного Wi-Fi scan-result receiver на время активности.
- Запрос Wi-Fi scan через WifiManager.startScan(); во время AR-прохода запросы выполняются не чаще одного раза в 35 секунд и остаются best-effort.
- Фильтрация точек маршрута по выбранному SSID с сохранением каждого BSSID как отдельной радиоточки.
- Полноэкранный AR-режим на Google ARCore: ARCore Session открывает заднюю камеру, GLSurfaceView рисует camera background через OpenGL ES external texture.
- Получение camera pose только при TrackingState.TRACKING; горизонтальная траектория строится по X/Z координатам ARCore в локальной системе проекта.
- Связь AR-поз и Wi-Fi-измерений по монотонному времени; старые/неподтверждённые Wi-Fi scan results не записываются как новые измерения.
- Локальная SQLite-база с записями проходов, точками маршрута и привязанными Wi-Fi-измерениями.
- Восстановление незавершённых сессий после неожиданного завершения приложения.
- Просмотр списка сохранённых проходов и повторное открытие маршрута с Wi-Fi-точками.
- Экспорт отдельного прохода в ZIP-архив homeradar версии 1 и импорт такого архива через системный выбор файлов.
- Проверка формата, размеров архива, координат, временных меток, RSSI и частот до импорта; импорт записывается в SQLite одной транзакцией.
- Живая отрисовка траектории на свободном 2D-поле без плана помещения.
- Цветные точки сигнала с отображением SSID, BSSID, RSSI, частоты и возраста измерения.
- Раздельное хранение времени измерения и времени получения Wi-Fi результата.

## Ограничения текущего AR-прототипа

- Для полноценного AR-картирования требуется совместимое с ARCore устройство и установленный Google Play Services for AR. На неподдерживаемом устройстве camera session не запустится.
- ARCore сообщает позу только при TrackingState.TRACKING. При потере tracking новые положения не добавляются, а интервалы без позы не следует считать измеренной траекторией.
- В текущем прототипе ARCore X/Z переводятся в локальные X/Y. Распознавание стен, комнат, дверей и построение плана помещения не реализованы.
- Время AR-позы помечается через SystemClock.elapsedRealtimeNanos() в момент обработки кадра, чтобы использовать временную шкалу Android для Wi-Fi association. Это приближение к времени съёмки кадра; точность синхронизации нужно проверить на реальном устройстве.
- Android ограничивает частоту Wi-Fi-сканирований; startScan() устарел и может быть отклонён системой. Интервал 35 секунд не гарантирует получение нового скана: при отказе Android приложение не будет выдавать кэш за свежие данные.
- Для чтения Wi-Fi результатов может требоваться включённая системная геолокация.
- Приложение не сохраняет видео или исходные camera frames; в SQLite остаются только точки маршрута и привязанные Wi-Fi-замеры. Полный IMU stream и Rust/Kotlin FFI ещё не реализованы.
- Запись останавливается при уходе Activity в фон; фоновый сбор пока не реализован.
- ARCore SDK остаётся зависимостью Google с отдельными условиями использования; его наличие в проекте не изменяет MIT-лицензию Rust Core.
- CI workflow проверяет компиляцию Android debug APK, но сам по себе не доказывает точность AR tracking, Wi-Fi coverage или синхронизации на конкретном телефоне.
